# 干员池与卡池 V3.3：技能表达、词条语义与冰冻联动

> 状态：设计修订稿，待引擎原型与机器人测试；纸面估分不代表实战平衡。

## 1. 本版改动

- 按用户给出的顺序修订前42名干员（芬至阿米娅）的技能卡面与结构化效果。
- 保留72名干员的卡ID、CP、攻击力、生命值与稀有度；未直接修改实际CP。
- 梓兰、真理、初雪增加寒冷/冻结联动；其他未指定技能保留V3.2效果，仅统一【群愈】为【群疗】。
- 新增 `native_traits_json`，区分来源单位固有特性与目标承受的状态；特性条目包含触发条件/处理器，不只存一个名称。
- 24张战术卡和12张支援卡仍以V3.2为基础，尚未全部补齐可执行的效果JSON。

## 2. 卡面语法

- 关键词数值默认1：`【补给】`、`【治疗】`、`【守护】`、`【集火】`、`【鼓舞】`。
- 大于1直接写在关键词后：`【守护】2`、`【鼓舞】3`、`【集火】2`。
- 触发短语统一简写：`回合开始`、`战斗开始`、`部署时`、`攻击前`、`攻击后`、`受伤后`、`杀敌后`、`战斗结束`。
- `杀敌后`映射 `on_kill`，仅表示来源干员被记为击倒来源的敌方干员离场。
- 卡面文本只负责显示；引擎读取 `trigger_events_json`、`skill_effects_json`、`attack_profile_json`、`native_traits_json`。

## 3. 语义分层：动作、状态、特性、事件

- 动作：`【压制】目标`、`【治疗】目标`、`【守护】目标`，表示执行效果。
- 状态：被【压制】、处于【中毒】状态、解除【冻结】，表示单位当前承受的结果。
- 固有特性：自身具有【剧毒】，表示来源单位携带的能力，不是给自己施加状态。
- 事件：受到【压制】时、解除【压制】时、受到治疗时，表示状态成功施加/移除或治疗实际生效的瞬间。
- 持续条件：处于【压制】状态时，只查询当前状态，不重复施加动作。
- “被动”仅用于技能触发类型，不是可施加给敌人的通用状态。要限制敌人，必须写明【缴械】、【眩晕】、【沉默】、【压制】或【冻结】。

建议事件：`on_status_applied`（状态成功施加）、`on_status_removed`（状态实际移除）、`on_healed`（生命实际增加）。压制/治疗/剧毒的动作、状态和接收者不应只靠中文文本推断。`on_healed`仅在目标HP实际增加时触发；满血、禁疗或治疗量为0均不触发。

## 4. 核心状态定义

### 4.1 压制

`【压制】目标`：目标下一次普通攻击攻击力-1（最低0）；该次普通攻击结算后移除。重复施加不叠加。

- “受到【压制】时”是状态成功施加瞬间事件。
- “处于【压制】状态时”是持续查询。
- “解除【压制】时”是状态实际移除事件。

### 4.2 治疗

`【治疗】目标`：即时恢复1点生命；数值大于1写在关键词后。治疗不恢复护盾，生命不超过最大生命。

- “受到治疗时”对应 `on_healed`，仅当HP实际增加后触发。
- “被治疗的友军”是目标筛选，不是状态。
- 禁疗阻止友方治疗；若卡牌明确写自我恢复，则该动作可配置为不受自身禁疗限制。

### 4.3 剧毒与中毒

- 【剧毒】是来源单位固有特性。
- 具有【剧毒】的单位普通攻击造成实际HP损失后，目标增加1层【中毒】。护盾完全吸收不施加。
- 【中毒】每层在目标下个己方回合开始造成1点生命伤害；多层按层数累计，之后清除到期层。
- 中毒伤害走统一伤害管线，可触发受伤/击倒；护盾可吸收。来源离场不自动清除已施加的毒层。

### 4.4 寒冷与冻结

这是适配回合制的简化转译，不复制原作攻速百分比：

- 【寒冷】：目标下一次普通攻击伤害-1（最低0）；持续至该次攻击结算后，或目标下个己方回合结束。
- 目标处于寒冷时再次受到寒冷，移除寒冷并转为【冻结】。
- 【冻结】：目标不能普通攻击、失去拦截资格，且不能触发自身技能（攻击触发、受伤反应和可沉默持续特性）；持续至目标下个己方回合结束。
- 冻结再次施加只刷新持续时间，不叠层；不移除已经存在的护盾、掩护、中毒等状态。
- 本版联动：梓兰造成实际伤害后施加寒冷；真理对已有寒冷目标再次施加寒冷并冻结；初雪战斗开始对同路生命最高敌人施加寒冷，若其已有寒冷则冻结。

原作中寒冷重复施加可转为冻结的辨识点，参考 PRTS 灵知与冻结条目；本作不引入攻速百分比或法术抗性。
来源： https://prts.wiki/w/灵知 ； https://prts.wiki/w/异常效果图鉴/冻结

### 4.5 缴械、眩晕、沉默、冻结

- 【缴械】：跳过下一次普通攻击，但保留拦截资格和技能/反应。
- 【眩晕】：跳过下一次普通攻击并失去拦截资格；不自动封锁全部被动/反应。
- 【沉默】：不能触发自身技能及可沉默持续效果；仍可普通攻击和拦截。
- 【冻结】：不能普通攻击、失去拦截资格，且不能触发自身技能；比缴械/眩晕更全面。

“进入被动状态”不是有效规则描述，必须明确具体被限制的行为。

## 5. 连击

`【连击】N`：一次普通攻击分为N段，连续攻击同一目标；每段伤害为 `max(1, 当前攻击力-1)`。

- 连击开始锁定目标；目标阵亡或离场，剩余段取消，不转移目标。
- 每段分别结算护盾和生命损失；【掩护】只抵挡第一段。
- 【集火】只加到第一段；【脆弱】在第一段实际触发后移除。
- 攻击前/攻击后效果每组连击只触发一次；受伤后效果按每段实际HP损失触发。
- 击倒/击杀只在单位真正离场时结算一次。

`lose_hp`表示直接失去生命值，不是受到攻击伤害；不触发掩护/护盾吸收，但仍须执行生命归零与击倒结算。

## 6. V3.3新增/需确认的引擎处理器

本版结构化数据使用以下通用处理器或字段，Codex实施前应逐项确认是否已有；缺失时新增通用实现，不得为单张卡写私有逻辑：

- `apply_cold_or_freeze`：目标无寒冷时施加寒冷；已有寒冷时清除寒冷并施加冻结。
- `conditional_attack_modifier`：按当前场上其他友方先锋数量动态计算攻击力修正，不写入永久成长。
- `grant_first_attack_modifier`：给指定阵营/职业单位登记本场首次普通攻击修正。
- `set_attack_profile_modifier`：战斗开始时登记本场攻击模式变化（银灰真银斩）。
- `lose_hp`：直接失去生命，不属于普通伤害，不被掩护/护盾吸收，但仍执行生命归零与击倒结算。
- `heal_and_shield`：对同一目标原子执行治疗和护盾。
- `native_traits_json`：加载来源单位固有特性；至少支持 `poisonous`（造成实际HP损失后施加中毒）和 `cannot_be_healed`（从友方治疗候选中排除自身）。
- 中毒状态需要支持层数、来源实例ID和目标回合开始时的到期结算。

`【群疗】`是本作效果关键词；`群愈师`仍保留为明日方舟原作职业分支名称，二者不能混为一谈。

## 7. 简易数值估分

沿用V3.2公式：

`纸面战力 = ATK × 2 + HP + 技能分`

`费用预算 = 4 + CP × 2`

`偏差 = 纸面战力 - 费用预算`

- -1至+1：预算区间内。
- 小于-1：纸面偏低，建议测试降费1CP。
- 大于+1：纸面偏高，建议测试加费1CP或降低技能收益。
- `suggested_cost_cp`只是建议，实际CP未变。技能分是人工估值，不是实战数据。

详见 `OPERATOR_BALANCE_REVIEW_V3_3.csv`。

## 8. 重点测试

1. 连击2的两段伤害、掩护、集火、脆弱和受伤事件。
2. 剧毒实际HP损失才施毒；多层中毒在目标回合开始按层数扣血。
3. 寒冷首次降低下一次普通攻击伤害1；再次寒冷转冻结。
4. 梓兰→真理/初雪的寒冷冻结联动及状态到期。
5. 先锋回合补给是否导致费用经济过强。
6. 德克萨斯部署伤害+眩晕+补给强度。
7. 推进之王条件攻击力必须动态增减，不能重复永久鼓舞。
8. 史尔特尔部署成长与战斗结束自损。
9. 医疗、群疗、禁疗与自我恢复边界。
10. 银灰真银斩、远山范围法术伤害、卡达跨路连锁的多路线收益。
11. 结构化效果JSON与中文卡面完全分离。
